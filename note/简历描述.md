# Flaunch —— 基于 Uniswap V4 Hook 的 Memecoin 一键发射平台

---

## 项目描述

Flaunch 是一个部署在 OP Stack L2 上、深度集成 Uniswap V4 Hook 机制的 Memecoin 发射协议。用户一键即可完成代币部署、流动性初始化和公平启动配置。协议核心由三个相互协作的模块组成：**FairLaunch**（公平启动）、**InternalSwapPool**（内部交换池）和 **BidWall**（出价墙），共同为新代币提供防操纵的启动环境和持续的价格支撑。

---

## 责任描述

- 负责设计并实现代币发射主流程（`Flaunch` + `PositionManager`），包含代币合约部署、ERC721 所有权凭证铸造及 Uniswap V4 流动性池初始化的完整链路
- 负责实现 **FairLaunch** 公平启动模块：在可配置的时间窗口内将代币价格锁定在固定 tick，通过 `BeforeSwapDelta` 机制拦截链上 swap，窗口结束后自动将筹集的 ETH 和剩余代币分别部署为两个不可撤回的单边流动性仓位
- 负责实现 **InternalSwapPool** 内部交换池模块：在 `beforeSwap` Hook 中优先从协议内部积累的手续费代币填充买入订单，降低对 AMM 价格的冲击，同时减少用户 gas 消耗
- 负责实现 **BidWall** 出价墙模块：将协议收取的 ETH 手续费在当前 tick 下方 1 格处自动建立单边买单流动性，在手续费积累达到阈值或仓位过期时自动 rebalance，为代币提供持续的价格托底

## 技术实现

### 代币发射主流程

- 使用 `LibClone.cloneDeterministic`（Solady）以 `tokenId` 作为 salt，通过 CREATE2 确定性部署 ERC20 Memecoin 合约，使代币地址在部署前即可预测
- 每次发射同步铸造一枚 ERC721 NFT 作为池的所有权凭证，转让 NFT 即转让池创建者权益（包括手续费分配比例）
- `PositionManager` 持有全量初始代币（`TokenSupply.INITIAL_SUPPLY`），统一管理 FairLaunch 仓位、宽区间仓位及各模块的手续费流转

### FairLaunch 公平启动

- 在 `beforeSwap` Hook 中判断当前是否处于公平启动窗口（`inFairLaunchWindow`），若在窗口内且为 ETH → Token 方向，则通过 `BeforeSwapDelta` 直接从虚拟仓位填充，完全绕过 Uniswap AMM，使价格在整个窗口内固定在 `initialTick`
- 利用 `TickMath.getSqrtPriceAtTick` 和 `FullMath.mulDiv` 在固定 tick 处计算 ETH/Token 的精确兑换比例，支持"精确 ETH 输入"和"精确 Token 输出"两种 swap 模式
- 禁止窗口期内的卖出（revert）和流动性修改，从机制层面杜绝预购抢跑
- 窗口关闭时，根据 `nativeIsZero` 标志自动计算 tick 范围（单边区间取最窄相邻 tick），分别调用 `LiquidityAmounts.getLiquidityForAmount0/1` 将 ETH 和剩余 Token 部署为两个永久不可撤回的单边流动性仓位；未售出的 Fair Launch 代币在 `PositionManager` 侧销毁

### InternalSwapPool 内部交换池

- 以抽象合约形式嵌入 `PositionManager`，在每次 `afterSwap` 收取手续费时通过 `_depositFees` 累积到 `ClaimableFees` 映射中（区分 ETH 和 Token 两个方向）
- 在 `beforeSwap` Hook 触发后，若检测到方向为 ETH → Token 且内部有可用 Token 手续费，则调用 `SwapMath.computeSwapStep` 以当前 pool 价格计算可填充的 ETH/Token 数量，直接通过 `PoolManager.take` + `Currency.settle` 完成结算，剩余部分再进入 AMM，从而减少了对链上流动性的冲击

### BidWall 出价墙

- 每次手续费分配后，`PositionManager` 调用 `BidWall.deposit`，将 ETH 手续费计入 `pendingETHFees`；当累积量超过动态阈值（`_getSwapFeeThreshold`，随历史累积量分档递增）时，触发 `_reposition`
- `_reposition` 先通过 `poolManager.modifyLiquidity` 移除旧仓位取回 ETH，再根据 `_beforeSwapTick`（swap 前的 tick 快照，避免使用 swap 后被影响的价格）以及 `nativeIsZero` 方向，调用 `TickFinder.validTick` 确定新的 `[tickLower, tickUpper]`（始终为当前 tick 下方的单 tick 区间），将全部 ETH 以 `LiquidityAmounts.getLiquidityForAmount0/1` 计算后部署为纯 ETH 单边买单
- 引入 `staleTimeWindow`（默认 7 天）机制：若池长时间无交易，在下次 `beforeSwap` 时提前 rebalance，确保出价墙始终跟随最新价格
- 代币创建者可调用 `closeBidWall` 提取 BidWall 中的 ETH，实现退出机制

## 技术栈

- **语言 / 框架**：Solidity ^0.8.26，Foundry（forge test）
- **核心依赖**：Uniswap V4（`IPoolManager`、`BeforeSwapDelta`、`BalanceDelta`、`TickMath`、`SwapMath`、`LiquidityAmounts`、`StateLibrary`）、Solady（`ERC721`、`LibClone`、`Ownable`、`Initializable`）、OpenZeppelin（`AccessControl`）
- **部署环境**：OP Stack L2，支持通过 Optimism `L2ToL2CrossDomainMessenger` 将 Memecoin 元数据跨链桥接至其他 Superchain 网络
